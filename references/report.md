# 诊断 JSON、计分规则与报告格式

## 诊断 JSON

每个品牌一个文件，`scripts/score.py` 读取它计算结果。完整示例见 `examples/suihe-bakery.json`。

```json
{
  "schema_version": "1.0",
  "brand": {"name": "品牌名", "industry": "行业", "date": "2026-10-01"},
  "items": {
    "C1": {"score": 3, "evidence_type": "用户陈述", "evidence": "具体证据"},
    "S4": {"score": null, "evidence_type": "待核实", "evidence": "缺什么信息"}
  },
  "source": {
    "statement": "一句话源力",
    "evidence_ids": ["C2", "U4", "M3"],
    "direction": "往哪放大",
    "tests": {
      "真": {"pass": true, "why": "理由"},
      "要": {"pass": true, "why": "理由"},
      "异": {"pass": false, "why": "理由"},
      "久": {"pass": true, "why": "理由"}
    }
  },
  "actions": [
    {"what": "做什么", "who": "谁来做", "done_when": "做到什么算完成", "item": "M3"}
  ],
  "not_doing": ["现在不做的事和理由"]
}
```

- `items`：必须包含 C1–C4、U1–U4、M1–M4、S1–S4 全部 16 项。
- `score`：0–5 的整数。`evidence_type` 为 `待核实` 时必须是 `null`。
- `evidence_type`：`资料可见`（封顶 5）、`用户陈述`（封顶 4）、`推断`（封顶 3）、`待核实`。
- `evidence`：每项都写。打分项写具体事实；待核实项写缺什么。
- `source`：源力未成立时写 `null`。C 不高于 3 分或 C 证据不足时必须是 `null`。
- `source.evidence_ids`：至少 2 项，至少 1 项来自 C，每项得分不低于 3。
- `actions`：1–3 件。档位不是“强”时，至少一件针对最短的维度。
- `not_doing`：1–3 条。

## 计分规则

1. **维度得分** = 已打分项之和 ÷（已打分项数 × 5）× 10，保留一位小数。某维度已打分项少于 3 项，记为“证据不足”，不出分。
2. **源力指数** `G = (C × U × M × S)^(1/4)`，保留一位小数。任一维度证据不足时不出 G。
3. **覆盖率** = 已打分项数 / 16。低于 13 项时，G 和档位标为“暂估”。
4. **档位**：
   - 弱：G < 5，或任一维度 ≤ 3。
   - 中：5 ≤ G < 8，且没有维度 ≤ 3。
   - 强：G ≥ 8，且没有维度 ≤ 3。
5. **补短板顺序**：维度得分从低到高。同分时按 C、U、M、S 的顺序。
6. **源力句状态**：
   - 未成立：`source` 为 `null`。
   - 待验证：四关有一关没过，或档位为弱。
   - 成立：四关全过，且档位不是弱。

## 报告模板

默认只交付这一页。细项评分表在用户要求时再附。

```markdown
# {品牌名} · 品牌源力策略

**结论**：源力指数 {G}/10（{档位；覆盖不足 13 项时写“暂估，覆盖 n/16 项”}）。{一句话：最短的是哪一项，先做什么。}

**源力**：{一句话源力}（{成立 / 待验证：哪一关没过，或“短板还没补上”}）
- 凭什么：{证据 1}；{证据 2}；{证据 3}
- 往哪放大：{一个方向；档位为弱时写短板补上之后的方向}

| 维度 | 得分 | 一句话依据 |
|---|---|---|
| C 核心价值与文化 | 7/10 | … |
| U 用户连接 | … | … |
| M 市场敏感度 | … | … |
| S 社会角色与价值 | … | … |

**策略五句**
1. 为什么：…
2. 是谁，不是谁：…
3. 说什么：…
4. 做什么：…
5. 怎么校准：…

**先做三件事**
1. {做什么}。{谁来做}，{做到什么算完成}。（补 {检查项}）
2. …
3. …

**现在不做**
- …

**待核实**：{缺什么信息，补了能确认哪一项；与 Jev 复核有分歧而维持原判的项也写在这里}

**提醒**：{合规或风险提示；没有就省略这一行}

> 依据所提供的资料做判断，不是市场调研，不构成效果承诺。品牌源力理论 · 易慧庭 · 包参谋
```

待核实项很多时，只写会改变结论的两三项，其余用一句“另有 n 项缺信息”带过。本该问用户却没机会问的问题，并入“先做三件事”或“待核实”。

证据不足、出不了总分时，结论行写：`**结论**：证据不足，暂时出不了源力指数（覆盖 n/16 项）。{一句话：最缺什么，先去拿什么。}`，维度表里没分的维度写“证据不足”，省略“策略五句”。

档位为弱时省略“策略五句”。

报告末尾注明“已做 Jev 复核”或“未做 Jev 复核”。

源力未成立时，“源力”一段改为一行：`**源力**：未成立。{原因}，先做下面三件事再回来看。`，并省略“策略五句”。


## 决策校验的回答格式

```markdown
**结论**：{做 / 改了再做 / 不做}。{一句理由。}
- 这个动作改的是：{表达 / 根 / 没明说但伤到根}
- 碰到的红线：{哪一条，或“没有”}
- 替代办法：{一个}
- 待核实：{会改变结论的事项；没有就省略这一行}

> 依据所提供的资料做判断，不构成效果承诺。品牌源力理论 · 易慧庭 · 包参谋
```

决策校验不需要诊断 JSON，也不运行脚本。

## 复测报告格式

```markdown
**结论**：源力指数 {旧} → {新}（{档位变化}）。
- 变了什么：{哪一项，升还是降}
- 为什么：{对应的事实}
- 接下来先做：{一件事}
```
