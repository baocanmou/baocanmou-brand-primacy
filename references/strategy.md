# 从评分到策略

## 1. 按档位决定做什么

档位由脚本给出，不要自己改。

| 档位 | 这次交付什么 | 不做什么 |
|---|---|---|
| 弱 | 指出最短的一项，给出补证据、补做法的三件事。C 高于 3 分时可以写一个“待验证”的源力候选句，“往哪放大”写短板补上之后的方向 | 不写策略五句，不把候选句当结论，不谈现在就放大 |
| 中 | 源力卡 + 策略五句，三件事的头一件用来补短板 | 不把预算主要投向传播 |
| 强 | 源力卡 + 策略五句，重点是放大和坚持 | 不建议换方向 |

| 证据不足（出不了总分） | 说明哪几项缺证据，三件事全部用来取证：先取 C 和 U 的证据 | 不写源力句，不给档位，不谈放大 |

C 不高于 3 分时，无论其他项多高，都先回去找根，不写源力句（脚本会拒绝）。给一个没有根的品牌写漂亮的源力句，等于替它编故事。

## 2. 找根：写源力卡

源力不是想出来的，是从高分证据里认出来的。按这个顺序找：

1. **C 里不肯将就的事**：C2 的底线，C1 的初心。
2. **U 里顾客真正买的东西**：U1 的需求，U4 的顾客原话。
3. **M 里别人做不到或不愿做的事**：M3。
4. **S 里因此受益的人**：S1、S2。

四处指向同一件事的地方，就是源力。写出 2–3 个候选句，逐一过下面四关，留下一个。

### 源力句的写法

一句话，说清“因为坚持什么，所以能为谁做到什么”。用老板和顾客平时说话的词，不用形容词堆砌。

- 可以：“汤底当天熬当天用，所以敢让顾客看着后厨吃饭。”
- 不可以：“以匠心品质，引领健康餐饮新生活。”

### 四关

| 关 | 对应维度 | 问题 | 不过关的样子 |
|---|---|---|---|
| 真 | C | 这件事有没有 3 分以上的行为证据？ | 只是愿望，或刚想出来的说法 |
| 要 | U | 顾客在不在乎？有没有顾客原话或购买行为支持？ | 老板自己感动，顾客无感 |
| 异 | M | 换成对手的名字，这句话还成立吗？ | 同行都能原样说 |
| 久 | S | 放大之后，对顾客、员工、上下游是好事吗？出了事还说得出口吗？ | 靠透支某一方才能维持 |

四关都过，源力“成立”。有一关过不了，标为“待验证”，并把验证方法写进先做的三件事。没有候选句能过“真”这一关时，源力“未成立”，不写源力卡。

### 源力卡三行

- **源力**：一句话。
- **凭什么**：2–3 条证据，注明来自哪个检查项。
- **往哪放大**：一个方向，说明放大后顾客能感知到什么。

## 3. 策略五句

只在档位为中或强时写。每句一两行。写不出来就写“待定：缺什么信息”，不凑数。

| 句 | 回答什么 | 来源 |
|---|---|---|
| 为什么 | 这个品牌为什么存在 | C1、S1 |
| 是谁，不是谁 | 一句定位方向，加上 1–3 条明确不做的事 | 源力句、C2、M3 |
| 说什么 | 一句核心信息，加 3 个支撑点 | 源力卡的证据 |
| 做什么 | 源力落在哪 1–2 个顾客能感知的环节 | 接触、决策、使用、分享四个时刻 |
| 怎么校准 | 看哪个数、多久看一次、到什么情况要回头查。资料里没有基准时，用“连续两个月下降”这类相对变化，不自己定绝对数字 | U3、M4 |

“不是谁”比“是谁”更重要。没有明确不做的事，品牌就会什么都想要。

“说什么”只给方向和要点，不写广告语成稿，不做视觉。顾客接收信息有四步：先注意到、再理解、然后记住、买的时候想起来。所以核心信息要一句话能复述，支撑点不超过三个，并且长期重复同一件事。

## 4. 先做三件事

头一件针对最短的一项，其余按对结论影响的大小排。每件事写清：

- **做什么**：具体动作，下周一就能开始。
- **谁来做**：老板、店长、还是某个岗位。
- **做到什么算完成**：看得见的结果。
- **补哪一项**：主要对应的一个检查项。

不写“提升品牌认知”“加强用户连接”“优化品牌形象”这类不知道从哪下手的话。

用户在请求里同时问了一个具体动作（例如“要不要上新渠道”）时，按第 6 节判断，把答案写进报告的“结论”和“现在不做”或“先做三件事”，不另起一份。

## 5. 不做清单

列 1–3 条现在不该做的事，每条一句理由。常见的有：

- 最短项没补之前，不加大传播投入。
- 不为短期销量改动 C 里的底线。
- 不照搬同行的做法或说法。

## 6. 决策校验模式

用户问“这个动作该不该做”时使用，例如降价、换配方、开加盟、换口号、追热点。先读 [理论要点](theory.md) 的第 3、6 节。

1. **看根清不清楚**。已有源力卡或 CUMS 评分就直接用。没有时做快速评估：只看 C 的四项，加上这个动作直接碰到的检查项，按 [评分细则](rubric.md) 在心里过一遍，不必写 JSON、不必运行脚本。用户想要完整评分时，再走完整策略。
2. **判断这个动作改的是什么**：
   - **换表达**：改说法、画面、渠道、产品形态，根没动。
   - **动根**：明着改掉 C 里的底线或承诺。
   - **伤根**：没有明说改，但做法和底线相反。例如底线是“当天现做”，动作是“集中预制降成本”。这一种常见，也隐蔽。
3. **对照五条红线**：不偏航、不妥协、不浮躁、不复制、不停滞。
4. **下结论**，三选一：

   | 判断 | 结论 |
   |---|---|
   | 换表达，U 和 M 的证据支持 | 做 |
   | 换表达，但证据不够或做法有隐患 | 改了再做，写明改什么 |
   | 伤根 | 改了再做（去掉伤根的部分），改不了就不做 |
   | 动根 | 不做。确实想做，就用另一个名字单独做，不动原来的品牌 |

5. 附一句理由、一个替代办法，以及会改变结论的待核实事项（例如对方口头承诺的数字、顾客是否真的在乎这一点）。

C 的证据不够、看不出底线是什么时，不下结论：告诉用户需要先弄清哪一件事，并给出弄清它的办法。

## 7. 复测模式

每季度一次，或在重大调整之后。用同一份细则重新打分，把新旧两份 JSON 一起交给 `score.py --compare`。报告只写三点：哪项变了、为什么变、接下来先做什么。

分数下降先查是不是动了根，再查表达是否过时。
